## Phase Goal

**As a** user, **I want to** submit a problem and watch it move through the task lifecycle (`queued` -> `analyzing_problem` -> `completed`/`failed`) end-to-end on a real deployed stack, even before any AI logic exists, **so that** every later phase has a trustworthy infrastructure foundation to build on.

If a more deliberate pass is wanted, `/gsd mvp-phase 01` can re-derive it.

## Acceptance Criteria (ROADMAP Phase 1 Success Criteria 1-3, this plan's share)
- [ ] `docker compose up` brings up API, worker, PostgreSQL, Redis, and Garage together and the API responds to requests
- [ ] `POST /api/v1/tasks` returns `202 Accepted` with `task_id` + `status: queued`
- [ ] The task is enqueued via taskiq + Redis, picked up by a worker, and its status is visible via `GET /api/v1/tasks/{id}` with PostgreSQL as the single source of truth

Establish the single `uv`-managed `algorunner` package (INFRA-01 modular layout: `schemas/`, `storage/`, `worker/`, `api/`, `agents/`, `tools/`), the `tasks` table, and a working task submission -> queue -> worker -> status round trip against a live PostgreSQL + Redis, then containerize the full 5-service stack.

Output: a runnable `algorunner` package, `tasks` table + migration runner, FastAPI app, taskiq worker, and a 5-service Docker Compose stack that together satisfy INTAKE-01, ORCH-02, API-01, API-02, QUEUE-01, DATA-01, INFRA-01, and INFRA-02.
