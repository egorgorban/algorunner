Keep a module-level active-connection counter; it is only touched on the event loop, so no lock is needed. <flagged_assumptions>
- **Duplicate correcting on the Solver route:** a correction iteration routed to the Solver emits correcting from both the Solver and the Code Generator. Detecting "first node of this iteration" would need extra state for no user-visible gain; the UI collapses consecutive duplicates.
- **Accept-then-close for rejected sockets:** chosen over handshake rejection so the browser receives an actionable close code (4403 stop, 1013 retry). Nothing is sent and nothing is subscribed before the close.
- **Absent Origin is allowed** even with a non-empty allowlist (non-browser clients such as the live probe and tests). This matches the browser-only nature of cross-site WebSocket hijacking.
- **Prohibition recall (canon referral, not minted):** secret exposure through `/api/config` and cross-origin socket use are canon security items (`/gsd-secure-phase`), handled by T-04-02-01..03 below; `must_haves.prohibitions` is empty.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> GET /api/config | unauthenticated public endpoint |
| other-origin page -> WS endpoint | a malicious site can make the user's browser open a socket |
| any client -> WS endpoint | unbounded clients can open sockets, each holding a Redis connection |

| T-04-02-01 | Information Disclosure | api/routes/config.py | high | mitigate | Explicit `ClientConfig` built field by field (never a Settings dump); test asserts no secret value and no secret-like key appears in the body |
