<objective>
Close the loop that makes this phase's Core Value real: a Reviewer that evaluates the executed solution and a bounded, issue-targeted correction loop that either lands on a passing solution or a clean terminal FAILED result — never an unbounded loop, and never a false "passed" when execution actually failed.

Purpose: REV-01/02/03/04/05 — a structured `ReviewResult` (passed, issues, severity, required_changes) per D-00d covering correctness/algorithm-soundness/edge-cases/complexity-reasoning/code-quality (REV-01/02/03), full-history-carrying targeted correction routing (REV-04, D-05/D-06), and a hard `max_iterations` bound (REV-05, D-00e). Complexity is checked analytically via the required reasoning field only — per D-00g, empirical/runtime verification of the claimed asymptotic complexity is explicitly out of scope, no benchmarking is introduced here. D-05's issue-category -> node routing table is `costly` to reverse (bakes into conditional-edge structure) per CONTEXT.md's own rating — carried through explicitly on the routing task below.
Output: the Reviewer node with a deterministic execution-failure short-circuit, the pure `decide_after_review` router, the correction loop wired into `build_pipeline_graph`, and full prior-attempt context flowing into every correction-targeted node's prompt.
</objective>
