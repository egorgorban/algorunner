<objective>
Fix the production regression from Phase 2 plan 02-10 (merged at e0eba9e): every task fails with `error.code = UNHANDLED_EXCEPTION, message = "unexpected kwargs: user, group, extra_groups"`.

Root cause (verified): `run_in_process_group` in `src/algorunner/tools/process.py` passes `user=65534, group=65534, extra_groups=[]` to `asyncio.create_subprocess_exec` when the worker is root. The taskiq worker (and uvicorn) run on uvloop, and `uvloop.Loop.subprocess_exec` accepts only stdin/stdout/stderr/universal_newlines/shell/bufsize/preexec_fn/close_fds/cwd/env/startupinfo/creationflags/restore_signals/start_new_session/executable/pass_fds, so it raises ValueError before forking. Stdlib asyncio accepts the kwargs, which is why the unit tests, the host pytest run (non-root, default loop) and the Docker probe (plain `asyncio.run`) all passed.

Fix: perform the drop inside `preexec_fn` (supported by uvloop): a composed function that, only when the worker is root, runs `os.setgroups([])`, `os.setgid(65534)`, `os.setuid(65534)` and THEN the existing rlimit function. No identity kwargs are passed to `create_subprocess_exec` anywhere.

Purpose: restore task execution in the Docker worker without weakening CR-01 (uid separation is the security boundary) or CR-02 (process-group kill on every exit path).
Output: fixed `tools/process.py`; a uvloop-based regression suite; updated isolation tests; a Docker probe that runs on uvloop.

**uvloop facts the implementation depends on (read from site-packages of the project venv):**
- `uvloop/loop.pyx` (`subprocess_exec`, around lines 2793-2795): any keyword outside its supported list raises `ValueError('unexpected kwargs: ...')`. This happens in the parent before any fork, so it reproduces on a non-root host as soon as an identity keyword reaches it.
- `uvloop/handles/process.pyx` (`_after_fork`): `preexec_fn` runs in the forked child. If it raises, the exception class name and `str(ex.args[0])` are written to an error pipe, the child calls `_exit(255)` and never execs, and the parent raises `subprocess.SubprocessError('Exception occurred in preexec_fn.')` with the original error as `__cause__` (stdlib asyncio raises the same `SubprocessError`). If the exception carries no args, uvloop's serialization fails: the child still exits 255 without exec but the parent sees no exception. So the preexec function must only let `OSError` (always has args) propagate, never a bare argument-less raise.
- On Linux, `set_user()` at setuid time marks PF_NPROC_EXCEEDED when the CURRENT RLIMIT_NPROC is already exceeded, and execve then fails with EAGAIN. Therefore the rlimit function (RLIMIT_NPROC=0 for Python) must run after `setuid`, never before.
